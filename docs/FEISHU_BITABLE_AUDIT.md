## 10. 第三轮：历史操作人 / 评论回复·@·解决 / 多选与人员默认值（2026-11-09 夜）

截图：`docs/screenshots/r5-history.jpg`（历史带操作人）、`r5-comments.jpg`（回复 + @ 提及 + 已解决）、`r5-mention-picker.jpg`（@ 成员选择）、`r5-default-multi.jpg`、`r5-default-person.jpg`。

- **历史操作人**：迁移 0045 给 `bt_events` 加 `actor_id`（引用 users，删除用户置空）与 `actor_kind`。登录请求在 `requireUser` 中把当前用户放进 context（`store.WithActor`），所有带记录快照的写入路径都写入操作人：单元格/记录增删改（MutateRecordGuarded，含批量删除逐条调用）、看板拖卡、日期比较写入、字段类型转换引起的记录更新、通用 AppendBtEvent；匿名公开表单提交写 `actor_kind='form'`。历史接口返回 `actor {kind,id,name}`（姓名取工作区成员与直接分享成员，不含邮箱）；界面显示头像 +「沈墨 修改了记录」，表单为「表单提交 创建了记录」；迁移前的旧事件回退为「修改了记录」，旧的创建事件用记录创建者。
- **记录评论**：一层回复（父评论必须是同一记录的根评论）；`@` 弹出成员选择（工作区成员 + 分享成员，↑↓/Enter/Tab 选择），正文中的 @姓名 渲染为蓝色标签；被 @ 的人收到通知（复用文档评论的 mention/reply/resolve 通知），但服务端只保留**当前能看到这条记录**的人，锁定视图下看不到该记录的人不会收到预览。解决 / 重新打开，已解决的讨论默认收起，点「显示已解决 N」展开。新增记录级 `PATCH/DELETE /records/{rid}/comments/{cid}`；通用 `/api/docs/{id}/comments/{cid}` 的修改/删除对记录评论返回 404（修补了上一轮遗留：之前可绕过记录可见性去解决/查看记录评论）。
- **默认值**：多选字段为可多选的选项标签（按选项颜色），人员字段为成员下拉（与人员单元格编辑器同一成员列表）。

本轮仍未做：评论无表情回应、编辑 UI、附件；历史仍不含删除事件（删除后记录不可打开）。

补充修复（同晚）：
- 回复 / 解决通知同样只发给**当前能看到该记录**的人（父评论作者失去记录可见性后不再收到预览）。排查文档评论：文档本身已校验；但多维表格、幻灯片、云盘文件等非文档节点的评论此前不校验收件人权限，现统一要求当前查看权限（`store.WithNotifySkip` + 所有节点类型的角色检查）。
- 人员字段：分享给此表格的人（非工作区成员）现在出现在人员选择器与默认值中（只给姓名，不给邮箱），默认值必须是工作区成员或直接分享对象。默认值选择器改为可见的成员标签（`docs/screenshots/r6-default-person.jpg`）。
- 人员字段在 Jiange 中目前**只有单人模式**（单元格值是一个用户 id，无「允许多人」设置），所以默认值按字段设置保持单选；多人人员字段需要连同单元格格式、编辑器、筛选/排序/分组、CSV、公式一起做，未在本轮实现。

## 11. 第四轮：人员字段允许多选（2026-11-10）

- **数据模型**：`base_fields.multiple`（迁移 0046，仅 `type=person` 有效，`created_by` 恒单选）。单选单元格仍是裸用户 id 数字，允许多选后为 id 数组；所有渲染与查询路径同时兼容两种形态。字段编辑新增「允许多选」开关；开关翻转触发存量单元格转换（单→多 `n→[n]`，多→单保留第一个成员、空数组删除单元格），`fieldChangesCells` 使锁定视图依赖该字段时翻转被拒绝并发 reload 事件；不再适配的旧默认值自动丢弃（`validCell`：多选接受正整数 id 数组，单选仅标量）。
- **单元格与编辑**：完整模式逐成员头像+姓名 chips，紧凑模式第一个成员 + 「+N」；多选编辑器为与多选字段一致的弹层复选列表（头像+姓名、草稿随虚拟化保留）；单选与 `created_by` 维持原生下拉。TSV 复制为成员姓名（「、」连接），粘贴按姓名解析回 id（未知名跳过该格；遗留纯数字 id 也接受）。
- **筛选/排序/分组**：人员筛选值改为成员选择器（包含/不包含 = 成员多选 chips，等于/不等于 = 成员单选），服务端 contains/not_contains/is/is_not 编译为成员 id 归属判断（scalar 视为单元素集合），不再对 JSON 文本做 strpos（修复 "1" 误中 "[11,2]"）；gt/lt 家族保持数字语义（数组单元格天然不命中，两端等价）。锁定视图允许的算子集合不变。排序（SQL 与内存）按第一个成员 id 数值排序（顺带修复 Postgres 端此前按文本排序与内存不一致）；表格分组为飞书式：一条记录出现在它每个成员的分组里，组头显示头像+成员名，空值进未分组。自动化触发条件与填色规则走同一归属语义，筛选值输入同样换成成员选择器。
- **CSV**：导出人员/创建人为成员姓名（"; " 连接，仅工作空间成员导出时解析姓名——外部协作者保持导出 id，避免通讯录外泄）；导入按姓名分号/逗号拆分映射为 id，未知名报行错误，单选人员多于一人报错。`csvImportPlan`/`cellCSV` 增加成员映射参数。
- **公式与展示**：公式引用人员字段取成员姓名（多人「、」连接；单选也改为姓名，不再暴露裸 id）；记录标题多人连接姓名（未知名省略，不泄露 id）；记录历史变化值显示姓名；仪表盘分布图按成员逐个计数（多人各计一次）。
- **默认值**：允许多选字段的默认值为成员 chips 多选（按成员表顺序存 id 数组），单选维持成员下拉；服务端沿用默认值校验/填充管线（多选默认在新建记录未填该字段时整体填入）。
- 已知限制：自动化消息模板 `{{人员字段}}` 渲染为逗号分隔的 id（通知链路以 id 传递，姓名由客户端解析）；看板仍不支持按人员字段分组；人员字段依旧不进公开表单。

## 12. 第五轮：界面国际化 i18n（2026-11-10）

- **架构**：中文为源语言（key 即文案），英文走 `src/i18n/en.ts` 字典；`src/i18n/core.ts` 提供 `t(key, {vars})`（`{name}` 插值）、localStorage `jiange.locale` 持久化、首次访问按 `navigator.language` 检测；`@/lib/i18n` 的 `useI18n()` 让组件订阅语言切换重渲染，模块级 `t()` 供 React 之外使用。Vitest 注入 localStorage shim 并默认钉住 zh-CN（现有断言中文的测试不受影响）。
- **切换入口**：登录页右上角与侧栏账号菜单旁的「English / 中文」按钮（LocaleToggle）。
- **覆盖范围（本轮）**：应用外壳（登录/注册、侧栏两套、全局搜索、分享/协作者/权限设置、确认与输入对话框、通知、回收站、云盘侧栏）与多维表格模块（工具栏/筛选/排序/分组/行高/填色/卡片配置、表格、字段表单与菜单、记录详情/历史/评论、看板、日历、甘特、画册、仪表盘、自动化、CSV 导入、表单设置与发布、写保护提示、相对时间）。字段类型与筛选运算符标签在渲染处经 t() 翻译。
- **完整性测试**：`src/i18n/i18n.test.ts` 扫描全部 `t("…")` 字面量与经变量的标签映射（registry 字段类型、行高、通知类型、角色、权限选项），任何一个缺英文词条即失败。
- **已知边界**：服务端返回的中文错误文案本轮未翻译（客户端有稳定错误码，后续可按 code 映射）；文档编辑器、云文档页、幻灯片、公开页、通知中心页面等尚未迁移，留待后续轮次；语言偏好暂存浏览器 localStorage，未同步到用户资料。

## 13. 第六轮：撤销/重做、评论编辑与删除（2026-11-11）
