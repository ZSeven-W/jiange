# 文档标题一致性设计（尚未启用）

## 现状和目标

文档标题存在两份数据：协同文档中的固定标题块 `0:1` 和目录元数据 `nodes.title`。编辑正文标题后，旧客户端通过独立的、延迟的 PATCH 写目录；侧栏重命名仅写目录。网络离线、并发编辑、重排请求、关闭页面和历史还原都可能使两者分叉。目录中的旧值也可能是用户最后一次侧栏改名，不能推断哪一份才是用户想保留的内容。

目标是把固定标题块作为新的协同权威，目录标题作为同序号的服务端投影；明确保留并提供用户恢复旧分叉两侧的途径。Base 使用独立模型，不纳入本设计。

## 写入和广播

1. 普通协同操作和历史还原都必须在与追加操作相同的存储事务内计算投影。PostgreSQL 先锁 `doc_heads`，在该事务读取不超过 head 的最新快照及连续操作日志，再只应用实际入库且未重复的操作，更新标题投影、head 并发出事务内通知；Memory 使用同一把锁实现等价语义。多实例不能直接使用房间中可能落后的内存标题。
2. 物化过程应校验快照、连续序号、单条日志恰好一项操作及无待解决依赖。`0:1` 必须是可见的 title 块；缺失、删除或损坏时不能投影隐藏文字，也不能静默覆盖已有目录值。需要安全的错误和恢复路径。
   现有快照不保留全部已见操作 ID，因此物化过程无法单独证明跨快照没有操作身份冲突；必须依靠完整的数据库唯一约束，并解决数据库回滚导致历史身份及序号重用的问题。
3. 原文完整保留，不对协同标题裁剪、截断或默默归一化。当前侧栏输入的 200 码点限制与正文输入不同，统一限制之前必须明确对离线及旧客户端的兼容策略，不能拒绝已产生的草稿或截断现有文字。
   PostgreSQL `text` 不能保存 NUL 字符；旧标题或未确认草稿含 NUL 时，需要显式保留可导出的原内容并给出恢复路径，不能丢弃或伪装同步成功。对于超出 JavaScript 安全整数范围的操作 ID 及字符跨度，同样需要拒绝不兼容投影并保留恢复信息。
4. 新的显式重命名先读取用户可见的标题与准确 head，确认后按该 head 生成 CRDT 操作，并在提交事务内重验会话、权限和 head；若 head 改变则返回冲突，显示最新值并由用户决定，不能静默重试整段覆盖。离线尚未提交的并发输入可能仍按 CRDT 规则合并，需在产品中说明并测试。
5. 投影及操作提交后继续通过既有通知和房间追平机制广播；断线或失败不能提前 ACK。跨实例并发、重复批次、混合正文与标题操作、撤权、事务回滚及重连须有端到端测试。
6. 在数据库 head 锁内物化时，应避免为提取标题而渲染整篇文档，提供能检查标题块可见性及类型的定向读取方式，并验证大文档、高并发场景下的锁等待和内存开销。
7. 替换整段标题时，新插入操作必须引用不会被 GC 移除的永久根锚点。仅按 head 校验不足：同一 head 的压缩快照可能在生成操作后提交，并移除原快照中的已删除叶子。服务端生成操作应避免创建长期未确认的普通客户端副本，以免阻塞 GC 水位。

## 历史数据与兼容

- 上线前先按文档记录旧目录标题、当前协同标题、对应 head 和时间；当二者不一致时持久保存双方及文档标识，提供用户可见的比较、选择和恢复，不直接把一方当成历史事实。记录操作必须和 head 锁或 CAS 配合，避免在扫描与写入之间丢掉新的更改。迁移要支持分批、重试、中断续跑及损坏数据报告。
- 旧客户端的延迟 PATCH 与用户主动重命名在原协议中不可区分。新客户端应停止把本地编辑结果作为无条件 PATCH 镜像，使用显式重命名接口；服务端对旧版文档标题 PATCH 明确返回升级提示，而非用陈旧值覆盖协同内容。部署必须有版本门禁和升级提示，避免旧版静默失败。Base 的 PATCH 不变。
- 仅靠当前页面的编辑锁无法挡住已卸载页面发出的迟到 PATCH。提交结果未知时，仅重新读取一次标题也不能证明原请求不会稍后提交；需要持久幂等操作状态与可串行取消机制，并同时约束旧 PATCH，才能安全解除写入屏障。
- 历史版本可能删除原固定标题块或创建不同 ID 的标题块。此类还原不能假装完成：应在提交前拒绝并保留当前内容，或先设计经过验证的安全迁移；还原成功也需在同一事务更新标题投影。

## 候选接口

- `GET /api/docs/{id}/title-state`：授权后返回 `{title, head}`；若存在历史分叉还需返回可供恢复的冲突信息或引用。
- `POST /api/docs/{id}/rename`：接收 `{title, expectedHead}`；成功返回实际标题和新 head；期间有并发变化返回 `409 title_conflict`，不提交部分修改。
- 旧文档标题 PATCH 返回 `409 upgrade_required`；对包含其他字段的旧请求应在任何字段生效前整体拒绝。

以上接口只是候选契约，目前未启用。只有原子投影、冲突留存及恢复界面、兼容门禁和端到端验证全部完成后才能替换现有行为。
