# 普通表格隔离存储原型

状态：2026-11-14。此原型是后续普通表格的一部分，**未接入应用路由、云盘、现有节点或生产迁移**，不是可用的飞书表格替代品。`server/internal/sheetstore/schema.sql` 仅用于隔离数据库测试，不能直接用于现有或生产数据库。

新客户端已对未知或缺失节点类型使用独立提示，并限制文档同步只连接已知文档；这是接入准备，不构成普通表格入口，也无法约束已部署的旧客户端。服务端类型协议、升级顺序和版本门禁仍须完成。

## 当前能力

- 创建工作簿时一次性建立一张工作表、100 行、26 列及创建者管理授权。行列使用独立稳定 ID；创建请求按账号、空间及 mutation ID 留存回执，同请求重试返回原工作簿，不同内容复用 ID 返回冲突。
- 单元格批量写入按工作簿和账号持久记录 mutation ID 与规范化后的内容摘要；所有单元格的预期版本同时成立才提交。重复请求返回原回执，空字符串仍保留版本墓碑，防止旧版本把已清空的单元格误认为从未存在。
- 每次读取、写入和查询回执都检查会话与显式工作簿授权；PostgreSQL 在事务内锁定会话、工作簿和授权，提交前检查会话时间。原型的授权模型尚未与应用实际的云盘、继承和分享策略统一，不能对外开放。
- 每批最多 500 个单元格、2 MiB 原始文本，单格最多 32 KiB；完整快照限制 100 张工作表、2 万行列、5 万个单元格和 16 MiB 文本。超出时返回明确错误，不截断数据。公式输入暂时拒绝，A1 地址处理见 `reference.go`，尚未接入写入或计算。
- 查询不到回执不证明先前请求一定未提交：原请求可能仍在执行或响应尚未到达。调用方需以相同 mutation ID 和原内容重试；禁止以新 ID 盲目重发。

## 验证与剩余工作

Memory 原型与隔离 PostgreSQL 使用同一套测试，覆盖并发重复创建和写入、版本竞争、批量回滚、清空墓碑、跨工作簿行列、权限撤销、会话过期、快照上限及返回值隔离；PostgreSQL 额外验证回执写入失败回滚、损坏回执拒绝、读取等待完整事务，以及授权或会话撤销与写入交错。Memory 还运行了 Go 竞态检测。测试数据库通过独立容器和独立 schema 创建，未使用工作区中未提交的迁移。

正式接入之前仍需：将工作簿身份与应用节点/云盘、回收站和分享权限统一；建立协议版本及旧客户端门禁；完善授权变更与读取的一致性；实现行列和工作表结构操作、分页/大表、公式计算、格式、导入导出、协作、HTTP API、离线草稿和真实编辑器。当前 Memory 原型持有独立测试身份状态，不能替代应用的 Memory 存储。快照限制及墓碑增长也需要分页和安全回收策略。
